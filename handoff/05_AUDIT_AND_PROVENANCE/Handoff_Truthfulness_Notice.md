# Certification boundaries and honesty requirements

* The original Gate1 decisions D-001–D-144 were approved historically, but their **complete verbatim primary register is not available** in this handoff. This limitation is not eliminated merely by adding a self-contained implementation contract. The new v1.0 default record supplies build behavior and must not be retroactively cited as old approvals.
* The previous v0.1 ZIP's local validation of 43/43 checks measured *static contents and abstract schedule witnesses*. It was **not a game implementation test**, a real browser test, or fresh-context Goldfish certification.
* The current handoff's hash/format/content-count preflight is likewise a **packaging test only**. Nothing here proves a game implementation works until a coding agent builds and executes it.
* The old desktop/mobile layout pictures failed visual review for Nerelle's on-land appearance. They are retained as negative examples, not the final game's look. The implementation blueprint explicitly requests a new waterborne solution and real screenshot approval.
* Copying PNGs to a flatter layout does not alter their original bytes and does not grant blanket authority to change locked bibles, routes, or story endings.
* Approved fonts are named, but font binaries are **not bundled** and must be obtained by the implementer from licensed sources with notices. Missing font binaries do not imply permission to swap brand-new visual families without owner approval.
* A coding agent should be able to proceed on engineering defaults in the new blueprint, but must clearly report any conflict with a more authoritative locked source. Only user approval (or an authoritative original later supplied) can resolve a genuine canon conflict.
